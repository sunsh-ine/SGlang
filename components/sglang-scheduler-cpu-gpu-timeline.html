Scheduler 同步 / Overlap 事件循环：CPU–GPU 时间线

横轴为时间，两个面板共用同一刻度、同一起点：上面是 event_loop_normal，下面是 event_loop_overlap；各 3 批（A/B/C）。

同色块 = CPU 占用；橙色 = GPU 前向 + 采样；纱纹 = 等待（CPU 阻塞 / GPU 空转）。

  • 收与组批（ingest_requests / get_next_batch_to_run）
  • launch（run_batch 仅下发）
  • CPU 阻塞等待
  • 处理结果（process_batch_result）
  • GPU 前向 + 采样
  • GPU 空转

代码对照

  • 同步：result = self.run_batch(batch) 返回时 GPU 已算完，随后 process_batch_result
  • Overlap：run_batch 只在 forward_stream 上 launch，立即返回，结果入 result_queue
  • 同一迭代内的 pop_and_process() 处理上一批（此时 GPU 在算当前批）
  • 等待点：process_batch_result 内部对 result.copy_done.synchronize()

为什么它能重叠

  • 两条 CUDA stream：调度侧 schedule_stream 与前向 forward_stream
  • 每轮只需 CPU 完成“收件 + 组批 + launch”，总量小于一批 GPU 计算时间，GPU 就不会断料
  • 每轮 _apply_war_barrier() 保证调度侧下一次写入不越过前向的读

何时退回同步

  • 首批无可重叠；无 batch 时走 on_idle()
  • 连续两个 prefill 批会被 is_disable_overlap_for_batch 拉回同步（换 TTFT）
  • 需要 grammar 同步的投机场景同样不重叠

刻度为示意值（一批 GPU 前向 + 采样 = 6 单位，CPU 收与组批 = 2、处理结果 = 2、launch = 0.5）， 用于说明重叠关系而非实测耗时；真实比例取决于模型、batch size 与 prefill/decode 比例。 行为依据 sgl-project/sglang @ bdf8886a。
