准备开始

点击播放或“下一步”，观察 lock_ref 如何在同一棵树上变化。

A、B 都持有完整路径

共享节点被持有两次，ref = 2；各自独占的叶子 ref = 1。

A 结束后

[40,50] 的 ref 归零，成为驱逐候选；[10,20] → [30] 仍被 B 持有，不能淘汰。

驱逐 A 的叶子后

[40,50] 被移除，B 的路径完整保留；[30] 仍不是叶子，因此继续驻留。

节点颜色 = 当前持有者集合，数字 = lock_ref。Root 不参与 lock_ref；ref = 0 只表示进入 LRU 候选，真正删除仍由显存压力触发。
