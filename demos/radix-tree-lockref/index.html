RADIXATTENTION / LOCK_REF

Radix Tree 的 lock_ref 状态

A、B 各自锁定自己使用的完整缓存路径。节点颜色表示当前持有者集合，节点右上角的 ref 就是 lock_ref 计数：仍有多少个运行中的请求持有这个节点。

  1. 01A、B 运行中
  2. 02A 结束后
  3. 03驱逐 A 的叶子
←/→ 切换 · 空格 播放/暂停 · R 重播 · Home/End 跳转 第 3 / 3 步

示例：A = [10,20,30,40,50] · B = [10,20,30,60,70]。Root 不参与 lock_ref。lock_ref = 0 只表示节点进入 LRU 驱逐候选；真正淘汰仍从叶子开始。第 3 帧里 [40,50] 被驱逐后，[30] 仍有一个子节点 [60,70]，所以不会被连带淘汰。
